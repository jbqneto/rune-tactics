O usuário compartilha apenas o Room ID público; o roomId interno do Colyseus fica encapsulado no servidor.
Room ID Público vs. roomId Interno O jogador e o agente só informam o Room ID público (RT- + 8 caracteres sem ambiguidade, único entre salas ativas). O roomId interno do Colyseus permanece apenas como detalhe técnico resolvido via lookup HTTP.
Segredo Isolado no Backend O servidor MCP obtém seu sessionToken chamando POST /api/pvp/session com actorType=mcp-agent. Não é necessário configurar PVP_SESSION_SECRET em Codex, Claude ou Antigravity.
Autenticação & Autoridade O Room ID identifica e localiza a sala, mas não é segredo. O controle de cada assento continua protegido pelo sessionToken HMAC validado em PvPRoom.onAuth e pelo ActorContext no MatchService.
Nota de configuração: A URL do servidor PvP é configurável via variável de ambiente VITE_PVP_SERVER_URL (padrão local: http://localhost:2567). Em produção, o mesmo servidor Node/Colyseus na porta 2567 (ou atrás de proxy reverso HTTPS/WSS) serve o frontend estático, a API HTTP e as salas WebSocket. O processo MCP nunca abre porta de rede própria.
